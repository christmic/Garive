# mobile/iosApp/

> **iOS app.** SwiftUI UI, native Apple frameworks. Thin tier —
> calls into the generated `mobile/shared/` XCFramework.

## Stack

- **UI**: SwiftUI (iOS 17+)
- **State**: `@Observable` macro
- **Async**: Swift Concurrency (`async`/`await`, `AsyncSequence`)
- **Min target**: iOS 17
- **Build**: Xcode (workspace generated by the KMP project)

## Module Layout

```
iosApp/
├── Sources/
│   ├── UI/        SwiftUI views, ViewModels, themes, navigation
│   ├── Bridge/    Swift ↔ Kotlin bridge (SKIE-generated entry points)
│   └── App/       App entry, lifecycle glue
├── iosApp.xcodeproj   or   iosApp.xcworkspace (generated)
└── README.md
```

## Conventions

- Views are `struct`s conforming to `View`. No `UIViewController`
  unless SwiftUI genuinely can't express something (rare).
- ViewModels are `@Observable` classes; UI observes via `@State`
  / `@Bindable`.
- Navigation via `NavigationStack` (iOS 16+).
- Push notifications: APNs (`UserNotifications.framework`).
- Keychain: native `Security.framework` for token storage.

## Bridge

- Host v1 is synchronous and enters through the generated KMP framework.
- Add SKIE when a later slice exports `Flow` or `suspend` APIs; do not
  hand-write coroutine conversion.

## Depends On

- `mobile/shared/` (via the KMP framework).

## Build

The executable contract gate builds the shared framework before SwiftPM:

```text
cd ../shared
java -classpath ../../experiments/engine-kt/gradle/wrapper/gradle-wrapper.jar \
  org.gradle.wrapper.GradleWrapperMain assembleGariveSharedDebugXCFramework
cd ../iosApp
swift test
```

SwiftPM links the XCFramework when it exists. A conditional local fallback
keeps source-only editing possible, but it is not the acceptance path.
